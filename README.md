# Autonomous Debugging Agent

A lightweight, locally running **Python debugging agent** powered by **Qwen2.5-Coder 1.5B** through **Ollama**. The agent follows an **agentic loop**: run tests, analyze failures, propose a code fix, validate the proposal, and repeat until the tests pass or the iteration limit is reached.

The project runs without paid LLM APIs and is designed for experimentation on modest hardware.

## How it works

```text
Python source + pytest tests
          |
          v
      Run tests
          |
    +-----+------+
    |            |
  Pass          Fail
    |            |
   Stop     Send errors and code
                 to local LLM
                      |
                Validate proposal
                      |
                 Apply fix
                      |
                Log and retest
                      |
                 Repeat loop
```

## Features by version

| Version | Capabilities | Status |
| --- | --- | --- |
| **V1** (`agent_v1.py`) | Test-driven LLM debugging and iterative retries | Successfully tested |
| **V2** (`agent_v2.py`) | Adds backup, rollback, JSON logging, and Python syntax validation | Basic success path tested |
| **V3** (`agent_v3.py`) | Adds feedback from previous attempts, duplicate/no-op patch rejection, unified diffs, and richer logs | Simple debugging example verified; broader evaluation pending |

> **Feedback memory in V3 is limited to the current run.** It is not persistent memory across executions.

## Requirements

- Python 3.11 (or a compatible Python 3 version)
- [Ollama](https://ollama.com/)
- Ollama model: `qwen2.5-coder:1.5b`
- Python packages: `ollama`, `pytest`

The prototype was developed on Windows 10 with 8 GB RAM. Docker is **not** required.

## Installation

1. Install Ollama, then download the model:

   ```bash
   ollama pull qwen2.5-coder:1.5b
   ```

2. Clone this repository and enter its directory:

   ```bash
   git clone <YOUR-REPOSITORY-URL>
   cd <YOUR-REPOSITORY-FOLDER>
   ```

3. Create a virtual environment and install dependencies.

   **Windows Command Prompt:**

   ```cmd
   py -3.11 -m venv .venv
   .venv\Scripts\activate.bat
   python -m pip install ollama pytest
   ```

   **macOS / Linux:**

   ```bash
   python3 -m venv .venv
   source .venv/bin/activate
   python -m pip install ollama pytest
   ```

4. Check that Ollama has the model available:

   ```bash
   ollama list
   ```

## Run the demo

The sample `buggy_code.py` contains an intentional error:

```python
def add(a, b):
    return a - b  # Intentional bug
```

The tests in `test_buggy_code.py` expect addition.

First, confirm that the tests fail:

```bash
python -m pytest -q test_buggy_code.py
```

Then run **one** agent version:

```bash
python agent_v3.py
```

Or compare earlier versions:

```bash
python agent_v1.py
python agent_v2.py
```

**Reset `buggy_code.py` to the intentionally buggy version before each experiment**, because a successful run modifies the source file.

Finally, verify the result:

```bash
python -m pytest -q test_buggy_code.py
```

V2 and V3 also generate timestamped backups and JSON logs in `backups/` and `logs/`.

## Initial results

In the simple arithmetic-bug experiment, the agent replaced `return a - b` with `return a + b`. The subsequent test run reported **3 passed**, with success confirmed on the second loop iteration. This is a proof of concept, **not** a benchmark of general debugging ability.

A separate local-model benchmark recorded approximately **18.86 tokens/second** and **21.79 seconds** total for its specific code-generation prompt. These figures are hardware- and prompt-dependent.

## Limitations and safety

- The prototype targets **one Python source file** and its predefined pytest test file.
- Passing tests does not prove that a patch is correct in every situation.
- AST validation checks **syntax only**, not semantics or security.
- **There is no sandbox.** Generated Python code and tests execute in the local environment. Only use trusted, controlled examples; do not run this agent on untrusted repositories or code.
- V3's feedback history is stored in memory during a run; JSON logs are saved separately for inspection.
- Multi-file debugging, systematic evaluation, and stronger patch verification remain future work.
